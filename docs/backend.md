# 서버 규칙

`server/`의 규칙을 적는다. 서버 코드를 고치기 전에 본다. 실행과 배포 순서는 `server/README.md`에 있다. 이 문서는 `CLAUDE.md`에서
나온 규칙집이라 단정형으로 쓰고, 규칙이 바뀌면 같은 커밋에서 고친다.

서버는 Cloudflare Worker다(TypeScript, Hono). 저장은 D1이다. 무료 플랜은 카드 없이 쓰고 한도를 넘으면 과금이 아니라
오류로 막힌다. KV는 하루 쓰기가 1,000번뿐이고 R2는 카드 등록이 필요해서 쓰지 않는다. 계정이 생기기 전까지는 `wrangler dev`로
로컬에서만 돌린다.

기대는 무료 한도는 요청 하루 10만, 요청당 CPU 10ms, 서브요청 50, D1 쓰기 하루 10만 행과 DB 500MB, 정적 에셋 파일 2만 개
(파일당 25MiB)다. 한 요청이 하는 일을 작게 둔다.

## 인증

- Riot 키, RSO `client_secret`, `STATE_SECRET`은 서버 비밀값이다. 세션 토큰과 로그인 코드는 SHA-256 해시만 저장한다. Riot 토큰은 계정을 한
  번 읽고 버린다. 세션은 90일이다.
- RSO는 앱과 서버 사이에 PKCE를 한 겹 더 둔다. 앱이 verifier를 만들어 challenge만 넘기고, 콜백은 서버 주소의 App Link
  `https://<서버>/auth/done?code=`로 일회용 코드를 준다. 가로챈 코드는 verifier 없이 세션으로 못 바꾼다.
- RSO state는 challenge, 만든 시각, 임의값을 서버 비밀값 `STATE_SECRET`(32자 이상)으로 HMAC 서명한 값이다. 로그인 시작은 세션
  없이 열려 있어 D1에 쓰지 않는다. 시작마다 쓰면 누구나 되풀이해 불러 로그인과 같이 쓰는 하루 쓰기 한도를 다 쓰게 할 수 있다.
  콜백은 서명과 10분 기한을 보고, 같은 state는 isolate 메모리로 한 번만 받는다. 다른 isolate로 가도 Riot 인가 코드가 한 번만
  쓰여 로그인 코드가 두 번 나오지 않는다.
- 로그인 시작과 콜백은 IP(`CF-Connecting-IP`)마다 1분에 20번까지다(시작 기준선). isolate 메모리에서 센다. 넘기면 시작은 429
  `too_many_requests`, 콜백은 `/auth/done?error=too_many_requests`다. 통신사 NAT 뒤에서는 여럿이 IP 하나를 쓰니 줄이지 않는다.
- 커스텀 스킴(`ovalit://`)은 쓰지 않는다. 다른 앱이 같은 이름을 등록해 남이 시작한 로그인의 코드를 받아 갈 수 있다.
- App Link는 서버의 `/.well-known/assetlinks.json`(서명 지문은 `ANDROID_CERT_SHA256`)으로 검증하고, 매니페스트의 호스트는
  `local.properties`의 `ovalit.server.host`에서 받는다. 앱이 안 열린 기기에서는 `/auth/done`이 `package=com.ovalit`을 지정한
  intent 버튼을 띄운다.
- 친구 초대 링크(`/i/{코드}`)도 같은 App Link이고, 앱이 없는 기기에서 보이는 페이지의 "앱에서 열기"도 같은 intent다. 링크는
  7일 가고 남은 기한이 하루 미만이면 새로 만든다. 초대 코드로 요청을 보내는 일은 실제 친구 저장소와 함께 붙인다.
- 초대 링크 페이지는 단톡방 미리보기 카드용 Open Graph 태그를 둔다. 누가 초대했는지는 적지 않는다. 그림은 정적 에셋
  `/og/invite-v{N}.png`(1200×630 PNG, 카카오톡이 SVG를 받지 않는다)이고, 카카오톡이 주소로 기억하니 바꾸면 N을 올린다.
  `robots.txt`는 `/i/`와 `/og/`만 연다.
- iOS Universal Link는 유료 개발자 계정이 있어야 해서 iOS에 RSO를 붙일 때 따로 정한다.
- `/auth/dev`는 RSO 없이 친구 흐름을 돌려 보는 문이다. `DEV_LOGIN=true`이고 `RSO_CLIENT_SECRET`이 없고 로컬 주소로 들어왔을
  때만 열린다. 배포 환경에는 `DEV_LOGIN`을 넣지 않는다. 로컬 주소 확인은 Host 헤더라 꾸밀 수 있어서, 배포 환경에 늘 있는
  `RSO_CLIENT_SECRET`으로 한 번 더 막는다. `wrangler dev`는 localhost에만 붙인다.

## 전적과 친구

- 전적에 닿는 경로는 모두 세션이 있어야 한다. VAL-CONTENT와 점검 안내도 레이트 리밋을 지키려고 세션 뒤에 둔다.
- 남의 경기는 서로 수락한 친구가 전적을 공개했을 때만 내려준다. 내가 안 뛴 친구 경기는 친구와 나 말고 모두 가린다. 가린 사람의
  플레이어 줄은 PUUID, 이름, 태그, 팀, 파티, 요원, 성적(`stats`), 티어, 관전 여부만 남기는 허용 목록이고 이름과 태그는 비운다.
  코치 줄은 PUUID와 팀만 남긴다. Riot이 필드를 더해도 저절로 새지 않게 빼는 목록이 아니라 남기는 목록이다. 커스텀 게임 이름은
  비우고 프리미어 팀을 가리키는 값은 뺀다. PUUID는 값이든 객체 키든 `anon-N`으로 바꾸고 파티 ID도 경기 안에서만 통하는 값으로
  바꾼다. 계정 레벨과 파티 ID는 느리게 바뀌거나 경기마다 같아서 다른 경기의 같은 사람을 잇는 실마리가 된다.
- 친구 요청은 같이 뛴 경기를 확인한 뒤에만 받는다. 상대가 앱을 쓰는지는 같이 뛴 사람에게만 알려준다.
- 친구는 한 사람에 200명까지다(사용자 결정, 200은 시작 기준선). 요청을 보낼 때와 수락할 때 두 사람 중 한쪽이라도 200명이면 409로 막는다. 내 쪽이면
  `friends_full`, 상대 쪽이면 `their_friends_full`이다. 수락은 한도 검사와 넣기를 한 문장으로 해서 동시에 여러 요청을 수락해도
  넘지 않고, 막히면 요청을 지우지 않고 남겨 친구를 정리한 뒤 다시 수락하게 한다. 친구 목록과 받은·보낸 요청은 최근 것부터
  200개까지만 내려준다.
- 친구 요청은 한 사람이 하루(UTC)에 30번까지 새로 보낸다(시작 기준선). 수락하거나 거절하면 `friend_requests` 줄이 지워져서
  `users.requests_day`와 `requests_today`로 센다. 넘기면 429 `too_many_friend_requests`와 다음 날 0시(UTC)까지의 `Retry-After`다.
  이미 보내 둔 요청을 다시 보내는 건 세지 않는다.
- 초대 링크 하나로는 요청을 20개까지 만든다(시작 기준선, `invites.uses`). 다 쓴 링크는 410 `invite_used_up`이고, `POST /invites`는
  다 쓴 링크를 다시 주지 않고 새로 만든다. 이미 친구거나 요청이 가 있는 사람이 누르면 세지 않는다. 하루 한도를 링크보다 먼저 세서
  한도에 걸린 사람이 거듭 눌러도 남의 링크 횟수는 줄지 않는다.
- 끝난 경기의 참가자는 D1 `match_players`에 한 번 적어 두고 친구 요청과 앱 사용자 확인에 쓴다. 부른 사람이 뛴 경기만 적는다.
  남의 경기 ID를 마구 물어 D1 쓰기 한도를 쓰게 할 수 없다.
- `match_players`는 경기마다 한 줄(PUUID JSON 배열)이다. 사람마다 한 줄이면 첫 수집 한 번이 500행을 써서 로그인과 같이 쓰는 하루
  쓰기 한도를 먼저 다 쓴다. 적은 지 10주가 지난 줄은 크론이 한 번에 100줄까지 지운다. 앱은 8주 안의 경기만 보고 경기는 끝난 뒤에
  적으니 앱이 볼 수 있는 경기는 늘 남는다. 지운 경기를 누가 다시 물으면 Riot에서 받아 다시 적는다.
- 참가자는 스코어보드를 열 때가 아니라 경기를 처음 받을 때 적는다. 스코어보드를 열 때 적으면 경기 원문이 isolate 메모리에 없을
  때 Riot을 다시 불러야 한다. Riot 레이트 리밋이 D1 쓰기보다 모자라다.
- 경기 ID 목록은 새 경기가 바로 보여야 해서 담아 두지 않고, 경기 상세는 30일 담아 둔다. Cache API는 `*.workers.dev`에서 담기지
  않아서 isolate 메모리를 먼저 본다. 둘 다 언제든 비므로 거기에 기대지 않고 앱이 저장한다.
- Cache API를 읽거나 담다가, 참가자를 적다가 실패해도 Riot이 준 값은 그대로 내려보낸다. 못 읽은 캐시는 없는 것으로 치고 Riot에서
  받는다. D1 무료 한도를 다 쓰면 쓰기만 막힌다.
- 라이벌은 서버에 두지 않는다. 기기에만 있다.
- 플레이어 카드는 정적 에셋 `/cards/{소문자 uuid}_{small|wide}.png`다. 저장소에 넣지 않고 `server/scripts/prepare-assets.mjs`가
  카탈로그에서 채운다. 티어 이름과 요원 역할 표는 `server/src/data/`에 두고 내려준다. valorant-api.com 자료로 스크립트가 만든다.

## ㅇㅂㅇ과 푸시

- ㅇㅂㅇ은 D1 `pings`와 `ping_members`(부른 순서 `position`)에 둔다. 서로 수락한 친구만 최대 4명이고(못 간다고 한 친구는 세지
  않아 나중에 더 부를 수 있다), 보낸 것이 끝나기 전에는 하나 더 못 보내며 하루 10번까지다.
- 시각은 지금부터 24시간 안이고, 하자고 한 시각에서 한 시간이 지나면 내려주지 않는다. 시작까지 5분이 안 남은 것은 "지금"이다
  (`Ping.isNow`, 알림의 `NOW_WINDOW_MS`도 같아야 한다).
- 같이 불린 사람 중 내 친구가 아닌 사람은 이름만 주고 PUUID는 그 ㅇㅂㅇ 안의 자리로 `anon-N`이 된다(사용자 결정). 친구를
  끊으면 두 사람은 서로의 ㅇㅂㅇ에서 빠진다.
- 푸시는 FCM HTTP v1 데이터 메시지다. 서비스 계정 키 `FCM_SERVICE_ACCOUNT`는 서버 비밀값이고, RS256으로 받은 접근 토큰은
  isolate 메모리에 둔다. 글은 보내지 않고 종류, 이름, 시각만 보내서 문구는 앱이 정한다. 한 요청이 쓰는 푸시는 서브요청 40개
  안이다. 기기 토큰은 사람마다 최근 3개만 두고, FCM이 없는 토큰이라고 답하면 `push_tokens`에서 지운다.
- cron이 5분마다 곧 시작할 ㅇㅂㅇ을 부른 사람과 간다고 한 친구에게 한 번 알리고, 끝난 것을 지운다. 몇 분 전에 알릴지는
  사람마다 고른다(`users.remind_before`, 10분·30분·1시간·받지 않기, 기본 10분, 사용자 결정). 보냈는지는 받는 사람마다 적고
  (호스트는 `pings.reminded`, 친구는 `ping_members.reminded`), 시간을 바꾸면 둘 다 비운다.
- 월요일 00:00 UTC(한국 9시)에는 주간 리포트 토픽 `weekly_report`로 보낸다. 앱은 설정의 주간 리포트 스위치를 따라 토픽을
  구독한다.

## 레이트 리밋

- Riot이 429를 주면 `Retry-After`가 지날 때까지 막고 503 `riot_rate_limited`로 답한다. 막는 범위는 `X-Rate-Limit-Type`을
  따른다. `application`은 우리 키의 몫이라 그 호스트 전체, `method`는 그 호스트의 같은 경로 틀(경로의 PUUID와 경기 ID를 묶은
  것)이다. 둘은 `Retry-After`가 없으면 10초다. `service`나 종류가 없는 429는 Riot 쪽 서비스가 바쁜 것이라 이 isolate에서만 그
  경로를 `Retry-After`(없으면 5초) 동안 쉰다.
- `application`과 `method` 차단은 D1 `riot_blocks`에 한 줄 적어 isolate끼리 나눈다. 429를 받을 때만 쓰고, isolate는 Riot을
  부르기 전에 5초에 한 번까지만 읽는다. 그래서 다른 isolate가 막힌 걸 알기까지 5초가 걸릴 수 있다. 풀린 줄은 크론이 지운다.
- Riot이 없다고 한 경기 ID는 10분 동안 기억해 다시 묻지 않는다.
- 같은 Riot 경로를 한 isolate에서 동시에 부르면 Riot에는 한 번만 가고 결과를 나눠 받는다. 같이 기다리는 쪽은 사용자 몫을 쓰지
  않는다.
- 한 사람이 앱 전체 몫을 몰아 쓰지 못하게 사용자마다 Riot 호출을 센다. 내 경기 목록은 10초에 한 번, 같은 친구의 경기 목록은
  1분에 한 번, 캐시에 없는 경기 상세는 1분에 120번까지이고 넘기면 429 `too_many_requests`와 `Retry-After`를 준다. isolate
  메모리에서 세니 막는다기보다 줄이는 장치다. 앱은 이 429를 받으면 새로 받을 경기가 없는 것처럼 둔다.

## 친구 비교 요약(계획)

아직 만들지 않았다. 실제 친구 저장소를 붙일 때 이렇게 만든다.

- 지금 친구 비교와 라이벌 대결은 친구 경기를 받아 기기에서 센다. 친구가 수백 명이면 친구마다 경기 목록과 상세를 받아야 해서
  앱 전체에 걸린 Riot 레이트 리밋을 친구 수만큼 곱해 쓴다.
- 그래서 앱마다 자기 경기로 주(월요일 0시)마다 고정 칸 합계를 세어 서버에 올리고, 친구는 요약만 받는다. 친구 비교 한 번이 서버
  요청 한 번이고 Riot은 부르지 않는다. 주는 기기 시간대로 자르는데, 한국 샤드를 쓰는 한국과 일본은 시간대가 같아(UTC+9) 친구끼리
  주가 어긋나지 않는다.
- 요약은 비율이 아니라 합계(경기·라운드 수, 킬·데스·어시, 전투점수, 피해량, 맞힌 부위별 탄)이고 액트와 큐를 같이 적는다. 기간을
  넓힐 때 더한 뒤 나눠야 평균의 평균이 생기지 않는다(`CLAUDE.md`의 지표 규칙).
- 요약도 Riot이 준 값이라 전적과 같은 선을 지킨다. 세션이 있어야 받고, 서로 수락한 친구가 전적을 공개했을 때만 내려준다. 친구를
  끊거나 연동을 해제하면 지운다.
- 경기 하나하나가 필요한 화면(S5 최근 경기, 친구의 S6, S7)만 친구 경기를 받는다.
