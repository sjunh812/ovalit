# Research: 오발있 기준 스펙

이미 내린 기술 결정을 결정, 까닭, 견준 안으로 옮겨 적는다. 결정의 원본과 지난 경위는 `CLAUDE.md`, `docs/backend.md`,
`docs/CONVENTIONS.md`, `docs/DECISIONS.md`에 있다. 끝에 아직 정하지 않은 것과 정하는 조건을 둔다. Technical Context에 "NEEDS
CLARIFICATION"으로 남긴 항목은 없다. 정하지 않은 것은 정하는 때가 정해져 있어 미룬 결정으로 적는다.

## 앱

### 화면 프레임워크와 출시 범위

- **결정**: Compose Multiplatform 한 벌로 쓴다. 출시는 안드로이드가 먼저이고 iOS도 낸다(2026-10-30 사용자 결정). 지금 iOS는
  시뮬레이터에서 돌리고 Xcode 프로젝트 없이 `shared/app`의 실행 파일을 앱 번들로 묶는다. iOS를 낼 때 Xcode 프로젝트(`iosApp`)를 둔다.
- **까닭**: TestFlight 외부 테스트에 Beta App Review가 걸려 iOS를 배포할 길이 없다. 그래도 화면 테스트(Compose UI Test)는 iOS
  시뮬레이터에서만 돌아서 iOS 타깃이 쓸모 있다.
- **견준 안**: 안드로이드 전용 Jetpack Compose(화면 테스트를 JVM에서 돌리려면 Robolectric이 필요), 별도 iOS 앱(배포 길이 없다).

### DI

- **결정**: Koin 4.
- **까닭**: Hilt는 KMP를 지원하지 않는다.
- **견준 안**: Hilt(회사 코드와 같지만 공유 모듈에 못 쓴다), 손으로 묶기(모듈이 14개라 관리가 어렵다).

### 화면 전환

- **결정**: Navigation 3을 `shared/app`에 두어 안드로이드와 iOS가 같은 뼈대를 쓴다(사용자 결정). 전환은 iOS 내비게이션을 따른
  0.3초 밀기이고 기본 크로스페이드는 쓰지 않는다.
- **까닭**: 기능 모듈은 진입 컴포저블까지만 내놓고 어디서 어디로 가는지는 한 곳에서 정한다. 기본 전환은 줄어든 화면 둘레로 아래
  화면 글자가 잘려 보였다.
- **견준 안**: 플랫폼마다 따로 둔 내비게이션(두 벌을 맞춰야 한다).

### 구조

- **결정**: nowinandroid에서 UDF, `sealed interface UiState`, `stateIn(WhileSubscribed(5_000))`, Repository 분리, convention
  plugin, `core/testing`을 가져온다. SyncWorker 주기 동기화, FTS, 20여 개 모듈은 버린다.
- **까닭**: 끝난 경기는 바뀌지 않아 주기 동기화가 필요 없고 검색 기능이 없다(닉네임 검색 금지).

### 경기 받기

- **결정**: `OfflineFirstMatchRepository` 한 곳에 받기 규칙을 두고 서버(`MatchRemoteSource`)와 기기 저장(`MatchStore`)은
  인터페이스로만 부른다. 첫 수집은 최근 50경기·8주, 그 뒤로는 경기 ID 목록을 견줘 새로 끝난 경기만 받는다. 앱을 다시 열 때는
  마지막 확인 뒤 10분이 지났을 때만 받는다. 첫 수집과 오래 쉬었다 와서 쌓인 새 경기(스무 판 이상, 화면이 모두 가려졌을 때)는
  WorkManager가 맡는다(사용자 결정).
- **까닭**: Riot 레이트 리밋은 앱 전체에 걸려 한 사람이 화면을 여는 만큼 모두의 몫이 준다. 실제 서버와 DB가 붙어도 규칙과
  테스트(`OfflineFirstMatchRepositoryTest`)는 그대로 두려고 경계를 인터페이스로 나눴다.
- **견준 안**: 화면을 열 때마다 받기(레이트 리밋 낭비), 주기 동기화(끝난 경기는 바뀌지 않는다).

### Riot 응답 읽기

- **결정**: 본문을 문자열로 받아 `decodeMatch`, `decodeMatchlist`로 읽고 Ktor `ContentNegotiation`에 걸지 않는다. DTO와
  `Match`로 옮기는 일(`MatchMapper`)은 `core/network`에 둔다.
- **까닭**: 읽다 실패하면 kotlinx.serialization이 응답 원문을 예외 문구에 담는다. 그 예외가 비정상 종료 보고로 나가면 PUUID와
  이름이 같이 나간다(헌법 IV).

### 지표 계산 위치

- **결정**: 모든 지표는 기기에서 센다(`core/model`). 무거운 계산은 ViewModel이 `Dispatchers.Default`에서 한다.
- **까닭**: Worker는 요청당 CPU 10ms라 50경기 집계를 감당하지 못하고, 서버가 지표를 세면 남과 견주는 분포를 만들 유혹이 생긴다.
- **견준 안**: 서버 계산(무료 한도와 헌법 I에 걸린다).

### 실패 안내

- **결정**: 저장소는 실패 까닭을 `OvalitError`(인터넷 끊김, 로그인 풀림, Riot 붐빔, Riot 응답 없음, 그 밖)로 던지고, 사용자가 한
  일이 실패하면 앱 맨 위 토스트로 한 줄 알린다. 저절로 한 일은 조용히 넘기고 다음에 다시 한다.
- **까닭**: 실패를 삼키면 사용자가 왜 숫자가 안 바뀌는지 모른다(FR-006).

### 사용 통계와 오류 보고

- **결정**: Firebase Analytics와 Crashlytics(Spark 무료). 화면 이름은 고정 표로, 값은 구간으로만 보낸다. `google-services.json`이
  없는 체크아웃은 그 기능 없이 빌드된다.
- **까닭**: 무료이고 카드 등록이 없다. Riot이 준 값을 보내지 않게 이름과 값을 거른다(FR-032, SC-007).

### 광고

- **결정**: AdMob 네이티브 광고 한 줄. 광고 단위 ID가 없으면 요청하지 않는다. 승인 뒤 제품 설명에 광고를 적고 ID를 넣는다.
  출시 전에 동의 창(UMP)을 붙인다.
- **까닭**: 헌법 V. 숫자를 읽는 중간(기간, 고정 칸, 달라진 점 사이)에는 두지 않는다(FR-034).
- **순서**: 심사 중에는 신청서와 제품 설명을 고치지 않는다. 설명을 고치는 것도 심사라 줄 맨 뒤로 갈 수 있다. 승인 직후
  `docs/RELEASE.md` "신청서와 다른 것" 표(광고, 파티 모집, 일본어 화면, 스코어보드, 앞으로 더할 친구 요청 푸시)를 제품 설명에 한
  번에 적고 그 뒤에 광고 단위 ID를 넣는다(T081).

## 서버

### 런타임과 저장

- **결정**: Cloudflare Worker(TypeScript, Hono)와 D1.
- **까닭**: 카드 등록 없이 쓰고 한도를 넘으면 과금이 아니라 막힌다. RSO가 Authorization Code 방식이라 `client_secret` 교환을
  서버에서 해야 하고 Riot 키도 앱에 넣을 수 없다.
- **견준 안**: KV(하루 쓰기 1,000번), R2(카드 등록 필요), 카드가 필요한 다른 서버리스(헌법 VI).

### 인증

- **결정**: RSO 위에 앱과 서버 사이 PKCE를 한 겹 더 두고 콜백은 서버 주소의 App Link(`/auth/done?code=`)로 일회용 코드를 준다.
  RSO state는 `STATE_SECRET`으로 서명해 D1에 쓰지 않는다. 세션 90일, 해시만 저장.
- **까닭**: 커스텀 스킴은 다른 앱이 같은 이름을 등록해 코드를 가로챌 수 있다. 세션 없이 열린 로그인 시작이 D1에 쓰면 누구나
  하루 쓰기 한도를 다 쓰게 할 수 있다.
- **견준 안**: 커스텀 스킴(`ovalit://`), WebView 로그인(앱이 비밀번호를 만진다).

### Riot 호출

- **결정**: 429는 `X-Rate-Limit-Type`에 따라 호스트나 경로를 `Retry-After`까지 막고 D1 `riot_blocks`로 isolate끼리 나눈다.
  사용자마다 호출을 센다(내 경기 목록 10초에 한 번, 같은 친구 목록 1분에 한 번, 경기 상세 1분에 120번). 경기 상세는 30일 담아
  둔다. 없는 경기 ID는 10분 기억한다.
- **까닭**: 막힌 동안 계속 부르면 앱 전체 몫이 깎이고 키가 막힐 수 있다.

### 친구와 가리기

- **결정**: 친구 요청은 같이 뛴 경기(`match_players`, 경기마다 한 줄, 10주 뒤 크론이 지운다)를 확인한 뒤에만 받는다. 내가 안 뛴
  친구 경기는 허용 목록으로 가리고 PUUID를 `anon-N`으로 바꾼다.
- **까닭**: 헌법 III. 사람마다 한 줄이면 첫 수집 한 번이 500행을 써서 하루 쓰기 한도를 먼저 다 쓴다.

### 푸시

- **결정**: FCM HTTP v1 데이터 메시지에 종류, 이름, 시각만 보낸다. 문구는 앱이 정한다. 크론이 5분마다 시작 전 알림을 보낸다.
- **까닭**: 보내는 양에 한도도 요금도 없다. 문구를 앱이 정해야 한국어·일본어를 따른다.
- **더할 것**: 친구 요청을 받거나 수락되면 알린다(FR-027, 2026-10-30 사용자 결정). 연동 4주 안에 친구를 맺는 비율(SC-003)이 성공
  기준이라 요청을 늦게 보면 그만큼 놓친다. 신청서에는 푸시 알림이 없어서 만들 때 `docs/RELEASE.md` "신청서와 다른 것" 표에
  한 줄 더한다(T059).

### 콘텐츠

- **결정**: 이름은 VAL-CONTENT, 역할 표와 티어 이름·엠블럼은 valorant-api.com 자료를 스크립트로 서버 `server/src/data/`에 두고
  내려준다. 앱 코드에 번호와 이름을 잇는 표를 두지 않는다.
- **까닭**: Riot 공식 자료에 요원 역할과 티어 이름이 없다.
- **더할 것**: 지금 `/content`는 VAL-CONTENT를 ko-KR로만 받고 티어 표도 한국어뿐이다. 앱 언어를 바꾸면 요원·맵·무기·티어 이름도
  바뀌어야 해서(FR-035) 실제 서버를 붙이기 전에 두 경로가 언어를 받게 한다(T083). 지금 앱은 가짜 저장소의 `FakeNamesJa`로
  대신한다.

## 디자인

- **결정**: 새 디자인은 Figma 파일 "오발있"에서 Figma Console MCP로 그린다(사용자 결정). 색은 변수 이름이 같은 "색 ·
  라이트", "색 · 다크" 두 컬렉션이다. 화면마다 번호와 화면 설명을 붙여 기획문서를 겸한다.
- **페이지**: 무료 플랜은 파일 하나에 페이지가 셋까지라(`createPage`가 막힌다) 페이지는 기획 개요, 기초, 화면 셋뿐이다. "화면"
  페이지 하나에 화면마다 한 줄씩 아래로 쌓고 줄마다 화면 섹션과 상태 섹션을 나란히 둔다(`docs/DECISIONS.md` 2026-10-30).
- **까닭**: 무료 플랜은 컬렉션 하나에 모드를 하나만 둔다(헌법 VI). 심사 목업은 고치지 않으니 새 디자인은 따로 둔다.
- **반영**: 화면이 확정되는 대로 앱에 바로 반영한다. 심사 목업에서 벗어나는 부분은 반영 전에 사용자에게 묻고
  `docs/DECISIONS.md`에 남긴다(spec.md Clarifications 2026-10-30).

## 홈 순서와 상태 줄

- **결정**: 홈은 머리, 큐 칩, 상태 줄, 카드 순서다. 상태 줄은 새 경기 진행 줄, 로그인 풀림, 점검 안내를 한 번에 하나만 두고, ㅇㅂㅇ
  카드는 카드 목록 맨 위다(사용자 결정, 2026-10-30). 로그인 풀림과 점검은 화면을 막지 않고 이 줄로만 알린다.
- **까닭**: 상태 줄은 밑의 숫자가 왜 그대로인지 알리는 줄이라 칩 바로 밑이 맞다. 로그인이 풀려도 저장된 경기로 리포트는 볼 수 있어서
  전체 화면으로 막을 까닭이 없다(FR-036).
- **견준 것**: 문서의 옛 순서(칩, ㅇㅂㅇ 카드, 진행 줄)와 로그인 풀림을 전체 화면으로 막는 안.

## 친구 비교 요약

- **결정**: 새 경기를 받을 때마다 그 경기가 든 주의 고정 칸 합계를 다시 세어 서버에 덮어쓴다. 사람마다 주당 한 줄이다. 친구를 끊으면
  요약은 지우지 않고 그 사람에게 내주지만 않으며, 연동을 해제하면 내 요약을 모두 지운다(사용자 결정, 2026-10-30, `docs/backend.md`
  친구 비교 요약).
- **까닭**: 주가 끝날 때만 올리면 이번 주의 라이벌 대결과 친구 비교를 셀 수 없다. 덮어쓰기 한 번이 D1 쓰기 한 행이고 새 경기가 있을
  때만 올려서 하루 10만 행 안에 든다(헌법 VI, SC-008).
- **견준 것**: 하루에 한 번 올리기(쓰기는 줄지만 친구 비교가 하루까지 늦는다).

## 친구 요청 알림 스위치

- **결정**: 설정의 알림 카드(분석 완료, 주간 리포트 옆)에 둔다(2026-10-30, `docs/screens.md` 설정). 사용자는 설정에 있어야 한다고만
  답해서 알림 스위치가 모인 카드로 정했다.
- **까닭**: 오발있? 카드는 파티 모집만 다룬다. 친구 요청은 파티 모집과 다른 알림이다.
